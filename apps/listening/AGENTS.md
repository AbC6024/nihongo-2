# 《聞いボード》專案指引（OpenCode）

## 專案目標

本專案是《聞いボード》：以「聽日文 → 打字 → 得分 → 錯題複習」為核心的響應式日文聽打學習遊戲。優先維持短局、快速操作、清楚回饋與行動裝置可用性。

## 修改前須知

- 每次工作先檢查現有程式架構、套件管理器、scripts、資料模型與相關測試。
- 優先增量修改並保留可運作功能；不得為了符合範例目錄而無故重寫專案。
- 不要假定專案一定使用 React、Vite 或 npm。只有在空專案時，才考慮使用 React + TypeScript + Vite。
- 開始修改前，簡短說明將採取的步驟，之後直接執行，不要只交付規劃或程式碼片段。
- 重要規則和共用邏輯要放在可測試的函式／模組，不要散落在 UI 元件。

## 遊戲規則不可破壞

- JLPT 難度為 N5、N4、N3、N2、N1。
- 一般模式每題基礎 100 分，每錯一次降低本題最後可得分 10 分：`max(0, 100 - wrongAttempts * 10)`。
- 一般模式同題答錯達 3 次後顯示「跳過」；跳過不獲本題分數、總分扣 50（總分最低 0），保存錯題並揭示答案。
- 一般模式答對／跳過揭示答案後自動進入下一題，不要求每題手動點擊。
- 句子模式顯示挖空句子、播放完整句音聲，只接受題目設定的答案或明確列出的替代答案。
- 複習模式在揭示答案後倒數 10 秒自動下一題，也提供手動下一題。
- 錯題本要提供音聲、星號重點複習、單筆刪除與清空確認。刪除錯題不得刪除遊玩歷史。
- 每日挑戰共 10 題：前 5 題來自一般題庫、後 5 題優先來自錯題／複習題庫；沒有複習題時使用一般題庫補足。
- 每日挑戰每答對一題 +200，錯答不扣分，跳過 +0，最高 2000；完成 10 題才算完成每日挑戰。同一天只計一次每日勝場。
- 計時歸零後鎖定本局；不得重複提交、重複計分或重複寫入題目紀錄。

## 外部資料、音聲與圖片

- 不可未確認授權就批次複製 Nihongo to Japan 原創題庫、OJAD 音檔或 いらすとや 圖片。
- 來源無法合法自動匯入時，實作 JSON／CSV 匯入器並提供示範資料，不要假裝已取得完整資料。
- 保留資料來源、授權及 attribution 備註。
- Web Speech API 是 fallback 機器語音，不能宣稱自動符合 OJAD 的アクセント。只有實際查核後才能標記音檔／聲調已驗證。
- 外部音檔或圖片失敗不得使遊戲崩潰。

## 技術品質

- 沿用現有框架與樣式；避免不必要的大型依賴。
- 計時使用時間戳差值，不要只靠每秒累加。
- localStorage 存取集中管理，處理損壞資料與 schema 版本。
- 清理 timers 與正在播放的語音，避免重複播放、記憶體洩漏與競態。
- 答案判斷、計分、每日挑戰、連勝與分析邏輯應盡可能有測試。
- 不可捏造測試結果；無法執行的驗證要明確說明。
- 手機優先設計；Enter 送出答案，Space 只有在焦點不在可編輯欄位時才重播音聲。
